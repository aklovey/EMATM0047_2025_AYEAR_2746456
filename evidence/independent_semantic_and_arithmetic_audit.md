# Independent semantic and arithmetic checks of deterministic components

This report is dated 2026-09-10 and covers the latest Phase56 set of 56 fixed questions, comprising 52 accepted traces and four unsuccessful questions without accepted output. It was generated by a newly written independent deterministic script with zero model calls. The existing local auditor, semantic_judge_passed field and pns_screening.oracle_value were not treated as computational truth.

## Findings

- Recalculated source yes/no labels agreed for all 56 questions when using the original probabilities, structural models and question direction. This checks label direction without establishing correctness of every natural-language derivation.
- Among the authors' source step5 expressions, 36 Boolean equations were internally consistent, 19 probability equations were numerically unequal, and one contained adjacent products without an explicit operator, creating a display ambiguity. The displayed source expressions cannot be used unchanged as strict semantic truth. Lack of parser support alone is not a mathematical error.
- For exact values, recalculation using the supplied estimand matched stored groundtruth for only 16/20 probabilistic questions at tolerance 1e-8. Including the 36 Boolean questions gives 52/56. All four differences involve NIE/arrowhead questions, and their yes/no directions are unchanged.
- All 52 accepted traces passed checks of segmentation, parent prefixes, concatenation of original prefixes and suffixes, and strict shortening with the same tokenizer. Independently parsed final JSON answers agreed with gold for all 52 after case normalisation.
- Extraction of purely numerical candidate equations covered only 13/52 accepted traces, with 135 safely computable equations and no local arithmetic inequality. This does not mean that all 52 complete traces passed semantic review.
- Complete natural-language semantics, robustness to alternative segmentation and the full judge's false-acceptance/false-rejection rates remain UNKNOWN. There are no human or expert annotations, and no labels were invented.

### Implemented probabilistic and Boolean calculations

| Type / graph | Independent implementation | Scope limit |

## Coverage and limits of candidate arithmetic checks

The safe AST permits only constants and bounded arithmetic and Boolean operations. It does not execute names, function calls, attribute access or arbitrary code. Chained equalities compare complete expressions on each side, avoiding an incorrect split of `a+b=c+d=e` into `a+b=c`. The extractor found 135 computable equations in 13 accepted traces, all consistent within displayed-precision tolerances. The other 39 traces were outside this conservative extractor's coverage. Absence of an extractable equation is recorded as uncovered, not as a semantic pass.

If a local arithmetic inequality is found later, it must be checked against subsequent corrections before classifying the whole path as a failure. The extractor does not establish correct estimand selection, factual/counterfactual worlds, variable mapping, graph direction, answer-leakage status, sufficiency of critical steps or robustness to alternative segmentation.

The pending-candidate files for the four unsuccessful questions contain 725 records. They provide context for questions with existing candidates but no accepted terminal output. Old correct/state values are not new semantic labels. A candidate marked correct but rejected cannot directly estimate a false-negative rate. Estimating the full judge's FPR/FNR requires independent complete-semantic labels under predefined criteria and the corresponding accepted/rejected sampling weights. The separate model-assisted blinded review conducted by the main task should identify its model, sampling and disagreements. It must not be presented as human expert review.

## Contextual review of four answer-scanner flags

| qid | Textual evidence | Finding |
|---:|---|---|
| 9577 | Reasoning repeatedly states Answer: No, and both its ending and final_content use capitalised No | A case-format difference rather than a semantic answer conflict. A lowercase-only regex missed it. |
| 23635 | Reasoning explicitly states that the indirect effect is positive, so a question about a negative effect is answered No; the JSON also uses No | The same case distinction. The normalised answer is correct, but the strict lowercase literal format fails. |
| 20959 | Final answer: yes is followed by the quoted instruction Check formatting: yes or no | The final no belongs to the permitted-format template rather than the conclusion. final_content is yes. |
| 30505 | The instruction Return exactly one JSON object: yes or no is quoted before Final decision: Yes | The last JSON no belongs to a template. Subsequent prose and final_content both answer yes. |

These checks qualitatively confirm the context of four answer commitments. They are not human annotations of complete reasoning paths and do not create four complete-semantic PASS labels.

The sole display ambiguity is q28145, which contains `0.59 * (0.30 - 0.27) 0.41 * (0.40 - 0.60) = -0.06`. There is no explicit operator between the two weighted products. The given estimand requires their sum, which is −0.0643 after adding a plus sign. Reading adjacency as implicit multiplication gives −0.0014514, also unequal to −0.06. The report nevertheless classifies this conservatively as a display ambiguity and does not treat a Python parsing failure itself as evidence of a mathematical error.
